temporal-datetimerange-picker — comprehensive example

One instance per card below, each configured with a different subset of options to show what's available. Pick a date (or range) in any card and its resolved value appears underneath — that's the callback firing with the picker's start/end dates.

1. Default

No options passed at all — every default applies: today's range, format MM/DD/YYYY, opens right, drops down.

2. Predefined ranges

ranges with a trailing "Custom Range" option (showCustomRangeLabel). Built directly with Temporal, no helper library needed.

3. Single date picker

singleDatePicker: true — one calendar, start and end are forced equal.

4. Date & time (24-hour)

timePicker: true, timePicker24Hour: true, timePickerIncrement: 15.

5. Date & time (12-hour + seconds)

timePicker: true with AM/PM and timePickerSeconds: true.

6. Month/year dropdowns

showDropdowns: true bounded to minYear/maxYear for fast navigation.

7. Min / max date bounds

minDate/maxDate passed as native Temporal.PlainDateTime objects (7 days back to 30 days ahead) — dates outside that window are disabled.

8. Max span

maxSpan: { days: 6 } — a Temporal duration-like object that caps how wide a range can be.

9. Week numbers

showWeekNumbers: true with locale.firstDay: 1 (weeks start Monday).

10. ISO week numbers

showISOWeekNumbers: true — standard ISO-8601 week-of-year numbering.

11. Custom locale

French-style labels, DD/MM/YYYY format, custom separator, and a Monday-first week.

12. Invalid & custom dates

isInvalidDate disables weekends; isCustomDate tags Wednesdays with a highlight class. Both receive the picker's date wrapper, which exposes .day() just like the old Moment-based one did.

13. Auto-apply, unlinked calendars

autoApply: true (no buttons, applies on second click), linkedCalendars: false (each calendar navigates independently), opens: 'center'.
